## گیت هاب چیست؟

پلتفرمی است که در آن توسعه دهنگان وب از سراسر جهان در آن گرد هم آمده و با یکدیگر ارتباط و همکاری دارند. در گیت هاب شما به عنوان توسعه دهنده وب می‌توانید پروژه‌های خود را با همکارانتان یا هر فرد دیگری که مایل باشید به اشتراک بگذارید و به صورت مشترک روی یک پروژه کار کنید. به این ترتیب به سادگی می‌توانید نسخه‌های قبلی یک نرم افزار را ارتقا دهید بدون این که تغییر یا اختلالی در نسخه‌های فعلی ایجاد شود

## گیت چیست؟

گیت معروف‌ترین و محبوب‌ترین سیستم کنترل ورژن در جهان است که اکثر برنامه‌نویسان از آن برای مدیریت پروژه‌هایشان استفاده می‌کنند
گیت با امکانات فراوانش برای حل تمامی این مشکلات به‌وجود آمده است و به‌رایگان دراختیار شما قرار دارد. به‌طور‌کلی، گیت برای مدیریت سورس پروژه و ثبت و ایجاد تاریخچه تغییرات و انجام پروژه‌های گروهی استفاده می‌شود

## تفاوت گیت و گیت هاب چیست؟

گیت سیستم کنترل نسخه‌ای است که برای مدیریت کدهای پروژه استفاده می‌شود، اما گیت هاب پلتفرمی است که برای میزبانی و به اشتراک‌گذاری کدهای پروژه به کار می‌رود

## HTTP چیست؟

Http مخفف عبارت Hyper Text Transfer Protocol است که به معنی پروتکلی برای انتقال ابرمتن‌ها می‌باشد. بر اساس این پروتکل، امکان ایجاد صفحات وب و سایت‌های اینترنتی فراهم شد. این پروتکل وظیفه برقراری ارتباط میان سرور و کلاینت را در یک شبکه کامپیوتری برعهده دارد. به عبارتی دیگر این پروتکل مسئولیت برقراری ارتباط بین سرویس دهندگان و سرویس گیرندگان وب را برعهده دارد.

## HTTPS چیست؟

https که مخفف «HyperText Transfer Protocol Secure» است، یک پروتکل امنیتی برای اینترنت محسوب می‌شود. این پروتکل برای حفاظت از داده‌هایی به کار می‌رود که بین مرورگر کاربر و وب‌سایت در حال تبادل هستند. https با رمزنگاری اطلاعات، از دسترسی و دستکاری غیرمجاز آن‌ها جلوگیری می‌کند.

## فرق بینشون؟

تفاوت http و https مانند فرق دو پاکت نامه باز و بسته است. یکی از پاکت‌ها مُهر‌و‌موم‌شده است و تا زمانی‌که آن را به صاحبش برسانید، به نامه درون پاکت دسترسی ندارید؛ اما پاکت دیگر باز است و قبل از رساندن آن به صاحبِ نامه، می‌توانید به‌راحتی نامه درون پاکت را بخوانید. پاکت مُهروموم‌شده همان https است.

## چرا بیشتر سایتا از اج تی تی پی اس استفاده میکنن؟

بیشتر وب‌سایت‌ها از HTTPS استفاده می‌کنند چون اطلاعات کاربر را رمزنگاری می‌کند و از شنود و دستکاری داده‌ها جلوگیری می‌کند، هویت سرور را با گواهی تأیید می‌کند، اعتماد کاربر را بیشتر می‌کند (مرورگرها HTTP را «Not secure» نشان می‌دهند) و روی رتبه سئو هم اثر مثبت دارد.

## ۴. URL

**URL** (مخفف Uniform Resource Locator) آدرس کامل یک منبع روی اینترنت است. با URL مرورگر می‌فهمد به کدام سرور وصل شود و چه منبعی (صفحه، عکس، فایل یا API) را دریافت کند.

### ساختار کلی

```
scheme://host:port/path?query#fragment
```

### بررسی یک URL واقعی

```
https://www.google.com/search?q=github&hl=en
```

| بخش | مقدار | توضیح |
|---|---|---|
| Scheme | `https` | پروتکل ارتباط با سرور (امن) |
| Host | `www.google.com` | آدرس سرور یا نام وب‌سایت |
| Port | `443` | پورت پیش‌فرض HTTPS است و در آدرس نوشته نمی‌شود |
| Path | `/search` | مسیر منبع روی سرور (صفحه جستجو) |
| Query | `?q=github&hl=en` | پارامترها به‌صورت `کلید=مقدار`؛ `q` عبارت جستجو و `hl` زبان است |
| Fragment | ندارد | بخشی از صفحه که مرورگر به آن اسکرول می‌کند (با `#` شروع می‌شود) |

### مثال کامل با همه بخش‌ها

```
https://www.example.com:443/products/list?category=books&page=2#reviews
```

| بخش | مقدار |
|---|---|
| Scheme | `https` |
| Host | `www.example.com` |
| Port | `443` |
| Path | `/products/list` |
| Query | `?category=books&page=2` |
| Fragment | `#reviews` |

**نکته:** همه URLها همه این بخش‌ها را ندارند. معمولاً فقط Scheme و Host حتماً وجود دارند و بقیه اختیاری هستند. پارامترهای Query با `?` شروع می‌شوند و با `&` از هم جدا می‌شوند.

## ۵. GET و POST

هر درخواست HTTP یک «متد» دارد که مشخص می‌کند مرورگر یا برنامه چه کاری با سرور می‌خواهد انجام دهد. دو متد پرکاربرد، GET و POST هستند.

### GET چیست؟

GET برای **دریافت اطلاعات** از سرور است. پارامترها در خود URL (بخش Query) فرستاده می‌شوند و درخواست، داده‌ای را روی سرور تغییر نمی‌دهد.

### POST چیست؟

POST برای **ارسال داده** به سرور است تا چیزی ساخته یا پردازش شود. داده در بدنه (Body) درخواست فرستاده می‌شود و در URL دیده نمی‌شود.

### تفاوت GET و POST

| ویژگی | GET | POST |
|---|---|---|
| هدف | دریافت اطلاعات | ارسال داده و ساخت یا پردازش |
| محل داده | در URL (Query) | در بدنه درخواست (Body) |
| تغییر داده روی سرور | خیر | بله |
| مناسب داده حساس (مثل رمز عبور) | خیر، چون در URL دیده می‌شود | بله (همراه HTTPS) |
| ذخیره در Cache و Bookmark | بله | خیر |
| محدودیت حجم داده | دارد (طول URL) | تقریباً ندارد |
| تکرار درخواست | بی‌خطر | ممکن است عملیات تکراری انجام شود (مثلاً دو بار ثبت سفارش) |

### GET برای چه درخواست‌هایی؟

- باز کردن یک صفحه وب
- جستجو
- دریافت لیست یا اطلاعات یک آیتم (محصولات، پروفایل، اخبار)
- دریافت عکس و فایل

**مثال واقعی (وب‌سایت):** جستجو در گوگل

```
GET https://www.google.com/search?q=github
```

عبارت جستجو در URL آمده است و گوگل نتایج را برمی‌گرداند.

**مثال واقعی (API):** دریافت اطلاعات یک کاربر از GitHub

```
GET https://api.github.com/users/octocat
```

سرور اطلاعات کاربر `octocat` را (به‌صورت JSON) برمی‌گرداند.

### POST برای چه درخواست‌هایی؟

- ثبت‌نام و ورود (Login)
- ارسال فرم (تماس، نظر، سفارش)
- آپلود فایل
- ساخت یک آیتم جدید (پست، حساب، repository)

**مثال واقعی (وب‌سایت):** فرم ورود یک وب‌سایت (مثلاً Instagram یا GitHub). نام کاربری و رمز عبور در بدنه درخواست فرستاده می‌شوند، نه در URL:

```
POST https://example.com/login

Body:
username=ali&password=********
```
